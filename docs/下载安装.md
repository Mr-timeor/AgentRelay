# AgentRelay 下载与按需启动

AgentRelay 为 DeepSeek Harness 的团队子智能体提供成员名单、开工和领取规则，以及面向复杂开发测试任务的可视化任务集。子智能体创建、消息投递、模型执行与会话恢复由宿主提供。

下载包包含已编译插件，解压后安装，无需 npm 或重新构建。独立运行包内 CLI 时需要 Node.js 22+。使用支持本地 bundle 和 agent-team 服务的 DeepSeek Harness，宿主适配状态以对应发布说明为准。

本页适用于 v0.1.1。包内 bundle 标识为 `dynamic-task-scheduler`。安装步骤以本页为准，ZIP 内说明和清单保留打包时的内容。ZIP、SHA-256 校验文件和发布验收结果见 [v0.1.1 发布页](https://github.com/Mr-timeor/AgentRelay/releases/tag/v0.1.1)。

## 1. 解压并安装

可用 PowerShell 的 `Get-FileHash -Algorithm SHA256` 核对 ZIP 与同次提供的 `.sha256` 文件。解压到要保留的目录，进入其中的版本目录。

```text
dynamic-task-scheduler-0.1.1/
  安装说明.md
  harness/bundle/        # 安装此调度器目录
  harness/view-bundle/   # 可选的旧模式独立图预览
  examples/desktop.patch.yml
  fixtures/development.json
  core/dist/
  manifest.json
  LICENSE
```

v0.1.1 发布包在 Windows Desktop 0.2.1-rc.3 通过隔离加载和冷启动，在 0.2.2-rc.1 通过隔离 CLI 安装和冷启动。两轮隔离验证使用本地模拟模型。同一发布包也在日常 0.2.2-rc.1 完成 CLI 安装、真实提示词加载和开发测试闭环。

先备份目标 profile 的配置并完整退出 Desktop。使用与 Desktop 相同 DSH_HOME 的宿主 CLI 安装。将 `<解压目录>` 替换为上例中包含 `harness` 的版本目录，按需替换 profile 名称。

```powershell
dsh plugin --profile desktop add "<解压目录>/harness/bundle"
```

`dsh` 指宿主附带的 CLI。未加入 PATH 时，通过实际启动器路径执行。PowerShell 调用带空格的启动器路径时使用 `&`。

CLI 可能建立指向解压 bundle 的 junction，安装后应保留该目录。宿主提供依赖，无需在解压目录运行 `npm install`。支持本地工具安装的版本也可使用 `plugin_manager / install_bundle`，本轮未直接调用该 Desktop 工具。

## 2. 启用待机入口

先备份当前 profile 配置。参考包内 `examples/desktop.patch.yml`，配置 agent-team 服务并启用调度器。

```yaml
- insert:
    - id: agent-team
      name: '@deepseek-ai/dsh-experimental-agent-team'
      config:
        maxMembers: 8
        maxTasks: 256
        maxMessageBytes: 65536
        disposalTimeoutMs: 5000
- id: dynamic-task-scheduler
  disabled: false
  config:
    onDemand: true
    leadSessionId: auto
```

已有 agent-team 服务时使用现有行。示例中的 `maxMembers: 8` 是 DSH 对单团队可创建的子智能体数量上限，包含已创建后失败的成员。本轮实际成员数取决于任务计划的 `agents`，一般先按开发、测试两个职责安排。若计划超过宿主允许的规模，先缩减或合并职责。

覆盖插件配置时只填写 id、disabled 和 config，name 由 bundle 提供。完整退出并重启 Harness 后，默认只有 `scheduler_manage` 加载入口，项目路径在启动时确定。

## 3. 用提示词启动

在要开发的项目工作区打开一个会话，发送以下提示。

```text
加载调度器。先听我说明开发与测试需求，再规划任务依赖、文件范围、交付物和验收条件。
先按开发和测试两名专项成员规划。列出分工和人数，需要增加时说明理由。
生成任务集和 HTML，各成员先回复分工与就绪情况，全部就绪后自动开工。
```

安装后只想确认加载时，可先在测试工作区发送「加载调度器。先只加载，等我说明任务。」从工具记录确认模型实际调用 `scheduler_manage({action:"load"})`，结果为 `startup.phase:"planning"`，输出路径指向当前工作区。此时插件绑定该 Lead，任务文件和 HTML 等到提交计划时才生成。

说明需求后，Lead 用 `prepare` 提交包含 agents 和 tasks 的项目 JSON。默认生成项目内的 `.scheduler/tasks.json`、`.scheduler/state.json` 和 `.scheduler/flow.html`，返回成员数量、分工和等待名单。任务拆分和职责规划由 Lead 完成，插件校验结构化计划并执行调度规则。[快速开始](快速开始.md)

已有任务文件时，prepare 不传 project 可恢复原计划，新需求在恢复开工后追加。插件保留已有计划和交付，准备阶段的任务保持暂停。

## 4. 等待全体团队子代理就绪

无需手动新建普通项目对话。Lead 按返回的 agents 列表，通过调度工具创建当前团队的子代理；仅当前团队内同名成员可被复用，独立普通对话不会自动加入。每个成员先阅读计划和任务卡，再调用 `scheduler_next({readySummary:"自己的分工与已就绪"})`。插件依据真实成员身份收集回复。

所有计划内成员回复后，插件解除准备暂停并开始自动派发。之后成员使用 next 领取、report 交付，waiting 时结束回合，依赖解除后恢复原会话。配置了 review 的任务仍由 Lead 检查实际交付和测试证据后接受。

在支持的 Harness 界面中，从 Lead 会话头部的子智能体目录打开实际成员，或选择“在侧边栏打开”。手动新建的同名普通对话不会收到这些成员的任务消息。

子代理默认以 `fresh` / `spawn` 创建，不复制 Lead 的聊天历史。请把必要要求写入任务计划、任务卡或委托消息；后续任务恢复成员自己的会话历史。

通过 `scheduler_status()` 可以查看 startup 阶段、就绪成员和等待名单，通过 taskId 读取任务详情。准备计划后，在 Harness 文件预览打开 `.scheduler/flow.html` 查看流程图。主调度器负责生成和更新 HTML，按需模式使用一个插件即可。

创建会话和就绪确认会使用宿主中配置的模型。正式任务在全体就绪后执行。工具调用和自然语言指令的具体响应由当前模型完成。

## 5. 返回待机与撤回安装

任务结束、没有未结束运行时，可让 Lead 调用 `scheduler_manage({action:"unload"})` 返回待机。任务、HTML、交付物和历史保留。未结束或 unknown 的运行先由 Lead 完成或确认停止并对账。

需要撤回安装时，先确认专项成员已停止，恢复安装前的 profile 配置，通过宿主插件管理通道禁用或移除插件，再完整重启 Harness。

升级到 v0.1.1 前停止旧写者，保留配置、旧安装目录和状态备份。新版使用状态旁的 `.lock` 阻止第二个写者；异常退出后，确认旧进程已停止再将残留锁移到备份位置，保留状态文件和 `.bak`。正常卸载会释放锁，无需手动处理。

## 固定项目兼容模式

已有固定任务与状态路径的用法可以显式配置 `onDemand:false`，继续使用原有四工具与 autoDispatch 设置。需要独立图预览时，再安装 `harness/view-bundle`，同样配置 `onDemand:false` 及 projectFile、stateFile、graphFile。该模式的路径示例见项目[快速开始](https://github.com/Mr-timeor/AgentRelay/blob/main/docs/快速开始.md)。
